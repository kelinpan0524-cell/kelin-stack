# 常见噪音分诊表（怀疑式分诊）

用于 `kelin-review` 的 Lead Judgment 环节处理外来审查意见（Codex、对抗审查、CI 机器人或同行评论）：逐条核实代码证据，**停止把每条审查意见都当成必改工单**。

## 分诊三类动作

- **修复（fix）**：意见指出了真实可达的正确性、安全、隐私、数据丢失、权限、并发或契约回归问题。修完后附提交号或验证输出关闭。
- **驳回（dismiss）**：意见命中下方低风险噪音模式，且当前代码或实跑结果能直接证伪。写清一句代码事实或命令证据后直接关闭，不改代码。
- **交人拍板（ask）**：意见涉及安全、数据、产品取舍、需求歧义或改方案/扩范围。不猜，带正反证据交人决定。

## 沉淀新噪音模式的格式

仓库长期复审反复遇到同一类误报时，按以下结构追加（`candidate` 1–2 次实证，`recurring` 多次实证，`strong` 窄边界且反复验证低风险）：

```markdown
### <模式短名>
- 置信度：candidate | recurring | strong
- 可驳回条件：<必须同时满足的事实>
- 不可跳过红线：<触发即必须修复或升级>
- 典型信号：<评论常见措辞>
```

## 内置高频噪音模式

### 1. 共享不变式或上游边界已兜底
- 置信度：recurring
- 可驳回条件：同一调用链上的共享校验、类型约束或前置入口已在当前 diff 或邻近代码里强保证该条件。
- 不可跳过红线：该保证只是口头假设、依赖时序，或跨异步/进程边界可能漂移。
- 典型信号：“这里没判空/没校验范围”，但调用入口已强校验且无其他外部调用方。

### 2. 为独立安装、迁移或并行切换有意保留的局部重复
- 置信度：recurring
- 可驳回条件：PR 说明或 `REVIEW.md` 已明确该少量重复用于保证单技能子集零依赖、或旧路径即将下线。
- 不可跳过红线：重复代码涉及权限、计费、安全校验或核心业务规则分叉。
- 典型信号：“两处辅助函数逻辑相似，建议抽取公共模块”。

### 3. 上游永不产出的假想输入或本机故意作弊场景
- 置信度：recurring
- 可驳回条件：触发必须依赖手工篡改本地状态、构造系统上游绝不产出的畸形文本，或仅对本地防误工具做恶意伪造绕过，且未触及安全/密钥/路径越界。
- 不可跳过红线：公网输入、鉴权、路径穿越、symlink 逃逸、密钥泄露、真实数据入库或门禁被放宽。
- 典型信号：“如果有人手动改坏状态文件或特意拼出某怪异字符串，脚本可能误判”。

### 4. 要求把窄错误条件改成宽泛兜底导致掩盖根因
- 置信度：candidate
- 可驳回条件：代码刻意只对特定错误（如 `ENOENT` 缺命令）走回退，对其他非零退出原样报错以防掩盖真实故障。
- 不可跳过红线：漏掉了同类别错误（如 `EACCES` 无执行权限），或失败后会残留损坏状态。
- 典型信号：“只在 X 报错时回退，建议对所有异常统一兜底”。

### 5. 陈旧扫描意见已在同 PR 后续提交修复
- 置信度：recurring
- 可驳回条件：评论针对旧 commit，当前 PR HEAD 已包含对应修复及测试，核对代码行号与测试均成立。
- 不可跳过红线：修复仅覆盖了部分分支或校验发生在副作用之后。
- 典型信号：复审工具重复引用上一轮已修复的问题。

### 6. 契约/文档漂移声称：先跑一条命令再判，不靠猜
- 置信度：strong
- 可驳回条件：声称测试与文档、索引或脚本漂移时，先确认对应校验命令确实覆盖所争议的断言，再在当前 HEAD 实跑；绿灯即作为铁证驳回。
- 不可跳过红线：命令跑红且属于普通测试/文档漂移时转 `fix`；若涉及门禁放宽类发现（`gate-scan`），一律优先按门禁规则转 `ask` 交人拍板，不自动修。
- 典型信号：“某测试/文档示例与最新改法不一致”。
