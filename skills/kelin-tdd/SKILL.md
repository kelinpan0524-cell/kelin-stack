# 测试先行

不是“必须有测试”，是**顺序**：先证明问题存在，再证明问题消失。

## 三步

1. **红**：写一个测试，跑一遍，确认它失败，并且失败原因是你预期的那个（不是拼写错误、不是环境问题）；
2. **绿**：写最小实现让它通过，不做多余设计；
3. **重构**：测试不变，改结构。改完再跑一遍，仍然绿。

## 修 bug 时

先写复现测试，再修。复现测试要能在旧代码上稳定失败，否则它证明不了任何事。

## 测试写什么

- 一个测试只验证一个行为；
- 断言结果，不断言调用顺序和内部实现；
- 边界值单独列：空、0、负数、超长、重复；
- 失败信息要能直接说明哪里错了。

## 什么时候可以例外

- 纯配置/文案改动；
- 一次性脚本；
- 外部系统不可模拟，且已经有人工验证步骤。

例外要在 PR 里写清楚，不要默默跳过。

## 反模式

- 先写实现再补测试，测试只是复述实现；
- 测试里 mock 掉真正要验证的东西；
- 为了让测试过而改断言；
- 一个测试覆盖十条路径，挂了不知道哪条。
