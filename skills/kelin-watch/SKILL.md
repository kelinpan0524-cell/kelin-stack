# 值守

> 命令里的 `$SKILL_DIR` 指本 Skill 所在目录的绝对路径，执行前先替换成实际路径。

值守的价值是**只报需要人动手的那部分**，不是把日志全刷一遍。

## 一次检查

```sh
node "$SKILL_DIR"/scripts/watch.mjs --pr 123
```

输出 JSON：每个 check 的名称、状态、链接；失败项分类与证据来源（`source: log | name | none`）；结论（`pass` / `pending` / `fail` / `no-checks`）。没有任何 check 时结论是 `no-checks`（退出 2），不当 pass 处理。

## 失败分类（证据优先级：日志 > 名字 > unknown）

对第一个失败的 check，脚本按其链接定位 Actions run/job，拉取失败日志的尾部（最多 8000 字符）判类；拿不到日志才用 check 名字兜底；名字也无信号就是 unknown。

| 证据 | 类别 | 特征 | 动作 |
| --- | --- | --- | --- |
| 日志 / 名字 | 代码 | 断言失败、类型错误、lint 失败 | 修代码，不重跑 |
| 日志 / 名字 | 环境 | 缺依赖、镜像拉不到、setup 步骤失败 | 修配置 |
| 日志 / 名字 | 网络 | 超时、5xx、连接重置、DNS | 允许重跑一次，仍失败就停 |
| 日志 / 名字 | 权限 | 401/403、token 过期 | 找人，不重试 |
| 无日志且名字无信号 | unknown | 证据不足 | 人看一眼，不自动开修 |

每个失败项带 `source`（`log` = 依据日志判类；`name` = 仅按 check 名字推断，需人复核；`none` = 无证据）和 `note` 说明。`source` 不是 `log` 的分类只作参考，**不要当成 code 就直接开修**。

## 轮询

- 默认只查一次；需要持续盯时用 `--interval 60`（秒），并设 `--max 10`（次数上限）；
- 只在 `pending` 时继续轮询，出现 `pass` / `fail` 立即返回；到上限仍是 `pending` 就带 pending 返回；
- 只打印状态变化：结论或失败集合没变就不重复输出，不刷屏；
- gh 调用失败直接退出 2，不猜结果。

## 升级

出现任一条就停：

- 同一失败连续 2 次重跑仍挂；
- pending 超过 20 分钟；
- 需要权限或密钥。

停下时给：卡在哪个 check、已试过什么、建议找谁。

## 部署后 canary

部署完成后按固定间隔看三样：错误率、延迟、关键接口成功率。只报**新出现或变差**的指标，并设停止条件（连续 N 次正常就停、或超过 30 分钟就停）。出问题先回滚，再分析。

## 陈旧 PR

超过约定天数没动的 PR：

- 先 rebase 到最新 main，跑 `git range-diff` 看上游改了什么；
- 重新跑检查和 review；冲突或行为变化写进 PR；
- 不再需要的 PR 明确关闭并写原因，不要挂着装死；
- 不要为了“有动静”而空跑 CI。

## 反模式

- 红了就重跑，不看第一个失败；
- 把网络抖动写成“代码有问题”；
- 无限轮询，人不在也一直跑。
