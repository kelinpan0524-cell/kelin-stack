# 重建上下文

目标：**用最少的读取，回答四个问题**。不是把历史全读一遍。

## 四个问题

1. 现在在哪：哪些做完了、哪些做了一半、哪些没开始；
2. 下一步：按依赖和风险，最该做的一件事是什么；
3. 有什么坑：已知失败、待决问题、环境限制；
4. 别碰什么：正在被别人改的文件、冻结的目录、不能动的数据。

## 读取顺序（按成本从低到高）

1. **任务板/文档**：项目 `AGENTS.md`、`README`、任务板里“进行中”的条目。AGENTS.md 缺失或明显过期时，先跑 `kelin-agents`；
2. **git**：
   ```sh
   git status --short
   git log --oneline -15
   git branch --show-current
   git diff --stat origin/main...HEAD
   ```
3. **未完成标记**：`TODO`、`FIXME`、`XXX`、测试里的 skip；
4. **会话记忆**：`~/.zcode/cli/memories/` 里与项目相关的条目（只看相关，不全量读）；
5. **必要时**才读代码细节。

## 输出

```markdown
## 现在在哪
- 已完成：……
- 进行中：……（停在哪个文件/哪一步）
- 未开始：……

## 下一步
1. 具体动作（为什么先做这个）

## 坑与待决
- 已知失败：……
- 待用户拍板：……

## 别碰
- ……
```

每条都要给出处（文件、提交号、任务 id），不要凭印象。文档里的说法先当声明，用 git、代码和测试验证过再当结论；老文档可能描述的是三年前的架构。

## 反模式

- 把整个仓库读一遍再回答；
- 只报“做了什么”，不说“下一步”;
- 把过期文档当现状，没有用 git 校验。
