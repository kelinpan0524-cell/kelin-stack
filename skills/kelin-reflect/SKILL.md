# 复盘

复盘的产出不是“总结”，是**下一次行为的改变**。

## 三个问题

1. 哪一步本来可以更早发现错误？
2. 哪条规则这次被违反了？为什么会违反？
3. 哪个判断是对的，值得写成默认做法？

答不出第 1 或第 2 条，说明这次没什么可沉淀的，直接说“没有新结论”。

## 结论落到哪

| 结论类型 | 写到哪里 | 例子 |
| --- | --- | --- |
| 稳定规则（跨项目、跨会话都成立） | `~/.zcode/AGENTS.md` 或项目 `AGENTS.md` | “本项目 import 必须带扩展名” |
| 项目状态（会变的） | 项目 README / 任务板 / `STATE.md` | “报价模块已上线，等待客户确认” |
| 跨设备共享的稳定事实 | `agent-shared/PROJECTS.md` | “NAS 地址、部署方式” |
| 只对本次会话有用 | 不写 | “这次用了临时脚本” |

**不要把项目状态写进长期记忆，也不要把一次性细节写进 AGENTS.md。**

## 写之前

- 查重：已有条目能不能改一行解决，不要新加一条；
- 写具体：`“x” 会失败，因为 y；改成 z` 比 `注意 x` 有用；
- 共享文档只做行级编辑，写前重读；
- 写 AGENTS.md 前先跑 `kelin-agents` 的 `agents-check`：超过 150 行先删再加，有失败项先修。

## 输出

```markdown
## 结论
1. 下次遇到 X，先做 Y（原因：Z）

## 已写入
- `AGENTS.md`：新增/修改了哪一条

## 没有沉淀的
- 只在本次有效的：……
```

## 反模式

- 写“沟通很重要”这种正确但没用的结论；
- 把一次偶发问题写成永久规则；
- 复盘完不改任何文件。
