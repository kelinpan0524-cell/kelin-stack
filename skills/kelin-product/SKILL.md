# 产品设计底线

这套底线解决的是“做出来才发现不对”：给错的人、在错的设备上、权限没设计、数据入口没防错、性能预算没定。**这些都要在 plan 期问清楚，不是上线前补。**

## 第一件事：问清用户和环境

不问清楚就别选技术栈。

| 要问 | 为什么 |
| --- | --- |
| 谁用：岗位、人数、是否外部客户 | 决定权限模型和界面密度 |
| 设备：公司电脑、老笔记本、手机、平板 | 决定性能预算和交互方式 |
| 网络：内网、弱网、离线 | 决定缓存、同步、包大小 |
| 使用频率：每天几十次还是每月一次 | 决定快捷操作和引导 |
| 数据量：百行、万行、百万行 | 决定分页、导入方式、数据库 |
| 合规：客户数据、手机号、金额 | 决定脱敏、审计、权限 |

答案写进 PRD 的“目标用户与环境”一节。**没有答案就标“待确认”，不要默认所有人。**

## 技术栈在 plan 期定

按环境选，不按流行选：

- 老设备、弱网：优先轻量、服务端渲染或少 JS；
- 内部工具：优先成熟、可维护，不追新框架；
- 数据量大：先定分页/索引/导入策略，再选库；
- 只有一两个人维护：优先少依赖、少构建步骤。

技术栈选择写清：选了什么、为什么、放弃了什么。不要“先用着再说”。

## 数据入口：上传必须防错

Excel / CSV 上传按这个顺序：

1. **预检**：文件类型、大小、编码、表头是否匹配、行数上限；
2. **解析预览**：先解析到临时区，展示前 N 行和总行数；
3. **清洗**：去空行、去重、日期/金额格式统一、必填校验；
4. **错误报告**：按行号 + 列名 + 原因列出，能下载错误清单；
5. **人工确认**：用户看过预览和错误数，点确认才写库；
6. **可回滚**：记录批次号，支持撤销整批导入。

任何一步失败都不写正式表。**不允许“上传即入库”。**

## 数据出口：导出要保真

- 导出格式、列顺序、表头、日期和金额格式与页面一致；
- 大数据量分页导出或流式导出，不一次性塞内存；
- 导出动作记审计日志（谁、什么时候、导出了什么范围）。

## 大数据：分页是默认

- 列表默认每页 20-50 行；
- 超过 1000 行必须服务端分页或虚拟滚动；
- 搜索、排序、筛选在服务端做，不把全量拉到前端；
- 导出和列表用同一套筛选条件，避免“看到的和导出的不一样”。

## 权限与审批：第一天就设计

**权限矩阵**写进 PRD：角色 × 资源 × 动作（查看/新增/编辑/删除/导出/审批）。

默认规则：

- 最小权限，默认拒绝；
- 申请人不能审批自己的单；
- 高风险动作（删除、导出客户数据、改金额、改权限）要双人复核或二次确认；
- 审批流每个卡点写清：谁审、看什么、超时怎么办、驳回后回到哪；
- 所有审批和权限变更留审计日志，能追溯；
- 权限变更本身也要审批，不能一个人给自己加权限。

目标是：**一个人的错误，不能变成所有人的损失。**

## 批量修改：数据多时必须能改

数据一多，人不能一条条点。批量修改按这个顺序：

1. 多选或按筛选结果全选，范围写清楚（本页 / 全部筛选结果）；
2. 只允许白名单字段批量改；
3. 输入新值，逐行校验；
4. **预览 diff**：将改多少行、冲突多少行、失败多少行；
5. 部分失败给行号 + 原因；成功的先不提交，或整批回滚；
6. 提交后按批次号可撤销；
7. 全程审计：谁、改了哪些行、旧值和新值。

超过 1000 行走异步任务：有进度、可取消、完成后通知。并发编辑用乐观锁，冲突让人选保留哪边。

## 导航与侧边栏：入口怎么放

侧边栏最容易被开发顺序带歪——谁的模块先做完，谁的入口就排最前面。定三条：

**按用途分组，不按开发顺序。** 常用入口一组、项目/模块类一组、内容/资料类一组。组与组之间拉开间距并加小标题；分割线可以留，但调淡，只用来划分大块区域，不要每个入口都画线。

**当前位置要一眼看见。** 选中项垫颜色醒目的底块，未选中项的对比度降一档但仍可读（不低于正文 4.5:1）；只靠加粗或轻微变色不算标注。

**固定两头，中间可滚。** 设置、帮助、账户这类低频但必须找得到的入口放底部固定；升级/付费入口可往下放，但不许折叠隐藏。入口多到排不下时，顶部和底部固定、中间区域滚动，别让整条侧边栏变成一个长滚动条。

另外两条硬规则：

- 入口顺序**定了就不随意改**——用户靠位置记忆找入口，改一次等于让所有人重新学；
- 同一个入口只允许有一个家，不为了“方便”在页面里再放一遍。

自查：入口超过 7 个就该分组；收起状态下列不全的，说明该归档或合并。

## 界面别一眼是 AI 做的

七步是减法，顺序不能乱：先砍最扎眼的，再调结构，最后修文案。

1. **去渐变和发光**：背景、卡片、按钮全换纯色，去掉光晕、毛玻璃、发光描边。AI 味最重的来源，先砍这个。
2. **颜色收到一个主色**：底色用纸感的浅色（不是纯白也不是死灰），强调色只留一个，只用在最该被看见的地方（进度、当前项）。
3. **emoji 换线性图标**：装饰性 emoji 全部换掉；图标统一线性、同一粗细、同一视觉重量。
4. **少用卡片**：不是每块内容都要装进圆角盒子；用留白和细分隔线分区，页面立刻透气。
5. **定主次**：一屏只有一个视觉重心，其余功能收成一排小图标；对照用户打开这一屏最想干的那件事。
6. **换字体**：标题可用衬线，数字用细衬线，正文保持无衬线；全站字重不超过三档。
7. **改文案**：把“欢迎回来，XX”换成具体信息（今天的日期、上次读到哪、还差多少）；按钮写清动作，“从上次停下的地方继续”好过“立即阅读”。

自查：截图后眯眼看——第一眼像模板，回做第 1、2、4 步；第一眼不知道该干什么，回做第 5、7 步。

## 下拉菜单和选择器不是一回事

长得像，用途完全不同，混用就是给用户挖坑：

- **选择器（select）**：填表用，选中的值留在框里，跟表单一起提交；外形像输入框，显示当前值。
- **下拉菜单（dropdown / 更多）**：命令集合，本质是一排藏起来的按钮；点一项立刻执行（导出、删除、跳转设置），触发按钮上不会留下“你选了什么”。

规则：

- 后台表格里**顶部筛选用带框的 select，右侧操作列用纯文字或图标触发的 dropdown**，不要做成同一个样式——用户点之前分不清是筛选还是删数据。
- 选项 **≤2 个**用单选或开关；**少于 5 个**直接平铺；再多才收进 select。
- 选项多（年份、城市）**加搜索**，面板高度控制在一屏扫得完（参考 256px），超出给滚动条。
- 用户能直接说出来的值（出生年份、金额）**让他输入**，别让人滑一百行。
- 弹层方向看下方剩余空间：够就往下、不够就往上；手机端选项多时从底部划出整块面板。**同一个 App 里不要上下左右随意弹。**

## 性能预算

写进 PRD，按目标设备定。默认参考：

| 指标 | 默认目标 |
| --- | --- |
| 首屏可交互 | 弱设备 < 3 秒，普通设备 < 2 秒 |
| 常驻内存 | 桌面工具 < 200MB |
| 首屏 JS | 能少则少，内部工具不为一屏动画加几百 KB |
| 列表 | 默认分页，单页不超过 50 行 |
| 缓存 | 静态资源长缓存，业务数据明确失效策略 |

不做花里胡哨的动效和重组件；先保证打开快、不卡、不崩。

## AI 解析：人只做决策

AI 负责把非结构化变成结构化，人负责确认和决策：

- AI 输出**先预览**，高亮不确定项和置信度；
- 每条结果可编辑、可撤销、可追溯来源；
- **人工确认后才落库**，不允许 AI 直接改正式数据；
- 批量结果给汇总：共多少条、多少条需人工处理；
- 出错时给原文件和行号，能回到原文。

## PRD 怎么写

必含：目标用户与环境、核心流程、导航结构（入口分组与层级）、权限矩阵、数据入口与出口、异常与防错、性能预算、验收标准、不做的事、技术栈与理由。

但 **PRD 不是一次做对**：

- 先写当前确定的部分，标“待确认”；
- 迭代中发现的新事实，回写 PRD 并记决策日志；
- 不追求一次写全，追求每次改动都有记录、下一个人能看懂；
- 旧 PRD 是历史，不是现状；收尾用 `kelin-neat` 对齐。

校验：

```sh
node skills/kelin-product/scripts/prd-check.mjs PRD.md
```

## 什么时候自动写 plan

不用等用户说“plan”。出现任一信号就该写：

- 跨 2 个以上文件，或涉及数据/权限/上传/导出；
- 需求里有“做个软件/功能/系统”“支持上传”“加权限”；
- 用户说不清验收，或上次类似任务返工过；
- 要给特定人群用，需要先问环境和约束。

反过来，单文件、文案、明确的小修，不要硬写 plan。判断标准在 `kelin-plan` 里。

## 反模式

- 先选框架再问用户用什么设备；
- 上传直接写库，出错再手工修；
- 列表一次拉全量；
- 权限最后加，发现到处是洞；
- 审批流只有一个人能批；
- AI 结果直接提交，没有预览；
- 侧边栏按开发顺序排入口，选中态只靠加粗；
- 升级/付费入口怕丑就藏起来，或塞进“更多”；
- PRD 写完就不改，代码和文档两张皮。
