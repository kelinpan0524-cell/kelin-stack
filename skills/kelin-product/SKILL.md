# 产品设计底线

这套底线解决“做出来才发现不对”：给错的人、在错的设备上、权限没设计、数据入口没防错、性能预算没定。都在 plan 期问清楚，不上线前补。

## 第一件事：问清用户和环境

| 要问 | 为什么 |
| --- | --- |
| 谁用：岗位、人数、是否外部客户 | 决定权限模型和界面密度 |
| 设备：公司电脑、老笔记本、手机、平板 | 决定性能预算和交互方式 |
| 网络：内网、弱网、离线 | 决定缓存、同步、包大小 |
| 使用频率：每天几十次还是每月一次 | 决定快捷操作和引导 |
| 数据量：百行、万行、百万行 | 决定分页、导入方式、数据库 |
| 合规：客户数据、手机号、金额 | 决定脱敏、审计、权限 |

答案写进 PRD“目标用户与环境”。**没答案标“待确认”，不默认所有人。**

## 需求澄清：最多 3 个问号

已确定的写下，不确定的标 `[待确认]`。只有“选错会明显改范围或体验、有多种合理解释、没有行业默认值”才值得问；其余用默认值，写进 PRD“假设”，让人能推翻。

- 最多 3 个会卡住开工的 `[待确认]`，每个写“谁回答、卡哪条需求”；其余写成带负责人的开放问题，不阻塞开工；
- **不发明需求**：没说的功能不补，没给的数字不编，每条能追到原话、数据或假设。

## 用户旅程写到能演一遍

不写“用户可以管理订单”，写具体的人：谁（“报价员小李”，不是“用户”）→ 从哪进来 → 3-5 个动作（看到什么、点什么、系统回什么）→ 价值在哪一刻落地（哪个数字/状态）→ 一条失败路径（断网、没权限、数据不对）。

写不出具体场景，说明没见过真实用法。一段旅程对应一组需求，每条需求能指回旅程。

## 先定胃口，再谈方案

设计前先问：**这件事值多少时间？** 不是估工期，是定花多少时间值得；时间定死，范围可砍。

每个方案写清：解决谁的什么问题、胃口（几天/几周）、做法（粗糙但完整）、兔子洞（第三方对接、历史数据清洗、权限边界、离线同步，能绕就绕）、这次不做什么。到点没做完，砍范围或停，不自动延期。

## 技术栈在 plan 期定

按环境选，不按流行选：老设备/弱网优先轻量、服务端渲染或少 JS；内部工具优先成熟可维护；数据量大先定分页、索引、导入策略再选库；一两个人维护就少依赖、少构建。

写清选了什么、为什么、放弃了什么。不要“先用着再说”。

## 数据入口：上传必须防错

Excel / CSV 上传按顺序：

1. **预检**：类型、大小、编码、表头、行数上限；
2. **解析预览**：先到临时区，展示前 N 行和总行数；
3. **清洗**：去空行、去重、日期/金额统一、必填校验；
4. **错误报告**：行号 + 列名 + 原因，可下载清单；
5. **人工确认**：看过预览和错误数，点确认才写库；
6. **可回滚**：记批次号，支持撤销整批。

任一步失败都不写正式表。**不允许“上传即入库”。**

## 数据出口与大数据

- 导出格式、列顺序、表头、日期/金额与页面一致；导出记审计；
- 大数据分页或流式导出，不一次塞内存；
- 列表默认每页 20-50 行，超过 1000 行必须服务端分页或虚拟滚动；
- 搜索、排序、筛选在服务端做；导出与列表用同一套筛选条件。

## 权限与审批：第一天就设计

**权限矩阵**写进 PRD：角色 × 资源 × 动作（查看/新增/编辑/删除/导出/审批）。

- 最小权限，默认拒绝；申请人不能批自己的单；
- 高风险动作（删除、导出客户数据、改金额、改权限）双人复核或二次确认；
- 审批卡点写清：谁审、看什么、超时怎么办、驳回回到哪；
- 审批和权限变更留审计；权限变更本身也要审批。

目标：**一个人的错误，不能变成所有人的损失。**

## 批量修改：数据多时必须能改

1. 多选或按筛选结果全选，范围写清（本页 / 全部筛选结果）；
2. 只允许白名单字段批量改，逐行校验；
3. **预览 diff**：改多少行、冲突多少、失败多少；
4. 部分失败给行号 + 原因；成功的先不提交，或整批回滚；
5. 提交后按批次撤销；全程审计旧值和新值。

超过 1000 行走异步：有进度、可取消、完成后通知。并发用乐观锁，冲突让人选保留哪边。

## 导航与侧边栏

- **按用途分组，不按开发顺序**：常用、项目/模块、内容/资料各一组；组间拉开距离加小标题，分割线只划大块。
- **当前位置一眼看见**：选中项垫醒目底块，未选中降一档但仍可读（≥4.5:1）；只加粗不算。
- **固定两头，中间可滚**：设置、帮助、账户放底部；升级/付费可往下但不许藏；入口多时上下固定、中间滚动。
- 入口顺序定了不随意改；同一入口只有一个家。

自查：入口超过 7 个就分组；收起状态下列不全的，归档或合并。

## 界面别一眼是 AI 做的

七步是减法，先砍扎眼的，再调结构，最后修文案：

1. **去渐变和发光**：全换纯色，去掉光晕、毛玻璃、发光描边。
2. **颜色收到一个主色**：纸感浅底，强调色只留一个，只用在最该被看见的地方。
3. **emoji 换线性图标**：统一线性、同粗细、同视觉重量。
4. **少用卡片**：用留白和细分隔线分区，别每块都装圆角盒子。
5. **定主次**：一屏一个视觉重心，其余收成一排小图标。
6. **换字体**：标题可衬线，数字细衬线，正文无衬线；字重不超过三档。
7. **改文案**：把“欢迎回来”换成具体信息（日期、上次读到哪、还差多少）；按钮写动作。

自查：截图眯眼看——像模板回做 1/2/4；不知道干什么回做 5/7。

## 下拉菜单和选择器

- **选择器（select）**：填表用，值留在框里跟表单提交，外形像输入框。
- **下拉菜单（dropdown）**：命令集合，点一项立刻执行，触发按钮不留“选了什么”。

后台表格顶部筛选用带框 select，右侧操作列用 dropdown，别做成同一样式；选项 ≤2 用单选/开关，<5 直接平铺，再多才收；选项多加搜索，面板一屏扫完（约 256px）；能直接说的值让他输入；弹层看下方空间上下弹，手机端多选项从底部划出，别在同一 App 里乱弹。

## 性能预算

写进 PRD，按目标设备定：

| 指标 | 默认目标 |
| --- | --- |
| 首屏可交互 | 弱设备 < 3 秒，普通 < 2 秒 |
| 常驻内存 | 桌面工具 < 200MB |
| 首屏 JS | 能少则少，内部工具不为动画加几百 KB |
| 列表 | 默认分页，单页 ≤ 50 行 |
| 缓存 | 静态资源长缓存，业务数据明确失效 |

不做花哨动效和重组件；先保证打开快、不卡、不崩。

## AI 解析：人只做决策

AI 输出**先预览**，高亮不确定项和置信度；每条可编辑、可撤销、可追溯；**人工确认后才落库**；批量给汇总（共多少条、多少需人工）；出错给原文件和行号。

## 验收标准：外行也能判对错

每条验收 = 可观察的结果 + 判断标准。

- **可测**：带数字、单位或能跑的命令（“3 分钟内完成”“10 万行翻页 < 1 秒”“`npm test` 退出 0”）；
- **技术无关**：写用户看到什么，不写“接口 < 200ms”“用了 Redis”；
- **关键路径用 Given/When/Then**：当 <状态>，做 <动作>，则 <结果>；失败路径至少一条；
- **优先级**：P1 单独做完就能演示、能验证；P2/P3 才依赖 P1。

反例：“界面美观”“功能正常”“性能良好”——没法判，等于没写。

## PRD 怎么写

**一份 PRD 只停在一个高度**：

| 高度 | 写到什么 | 不写什么 |
| --- | --- | --- |
| 项目/项目群 | 为什么做、给谁、成功指标、大方向顺序 | 功能行为、页面、接口 |
| 一个系统/功能 | 问题、用户旅程、能力清单（每条一个可验收结果）、边界 | 表结构、接口签名、页面细节 |
| 一个迭代切片 | 可测需求、异常和失败状态、改什么/不改什么 | 上层目标和指标，引用编号即可 |

混高度最难读：上面没结论，下面全是细节。

必含：目标用户与环境、用户旅程、能力与优先级、术语表（有领域名词时）、导航结构、权限矩阵、数据入口与出口、异常与防错、性能预算、验收标准、不做的事、技术栈与理由、待确认与开放问题（带负责人）。

篇幅：小项目一页，一个系统 2-3 页，写不下就拆下一层。术语表：客户/用户/订单/报价单第一次出现就定死，全篇只用一个词。

PRD 不是一次做对：先写确定的，标 `[待确认]`；新事实回写并记决策日志；旧 PRD 是历史不是现状，收尾用 `kelin-neat` 对齐。

校验：`node skills/kelin-product/scripts/prd-check.mjs PRD.md`

## 什么时候自动写 plan

出现任一信号就写：跨 2 个以上文件；涉及数据/权限/上传/导出；需求里有“做个软件/功能/系统”；说不清验收或上次返工过；给特定人群用。

单文件、文案、明确的小修不硬写，判断标准在 `kelin-plan`。

## 反模式

- 先选框架再问设备；
- 需求没问清就开工，代码写完发现做错了人；
- PRD 留七八个“待确认”，没人负责；
- 验收写“功能正常/界面美观”，靠感觉判；
- 目标、页面、表结构混一份 PRD；
- 到点没做完就延期，不砍范围；
- 上传直接写库，出错手工修；
- 列表一次拉全量；
- 权限最后加，到处是洞；审批只有一个人能批；
- AI 结果直接提交，没有预览；
- 侧边栏按开发顺序排，选中只靠加粗；
- 升级/付费入口藏起来或塞“更多”；
- PRD 写完不改，代码和文档两张皮。
