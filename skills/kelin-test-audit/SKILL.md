# 测试价值清扫

`kelin-tdd` 和 `kelin-guard` 负责**加**测试；这个 skill 负责**删**测试。24GB 的机器上，测试越积越慢，低价值测试会拖垮验证。

## 先扫一遍

```sh
node skills/kelin-test-audit/scripts/test-audit.mjs --root .
```

输出候选：文件、行号、模式、证据、问题。默认只报；要 CI 拦截加 `--fail`。

## 低价值目录

| 模式 | 为什么可疑 |
| --- | --- |
| 无断言 | 测试失败时抓不到任何行为 |
| 自己和自己比 | `expect(x).toBe(x)` 永远通过 |
| 只存快照 | 除了快照没有行为断言，改实现就红 |
| 永久跳过 | `skip` 变成了事实上的删除 |
| 复制夹具 | 为一条用例复制一大坨数据，维护成本高于价值 |
| 源码 grep 当契约 | 断言实现细节，重构就红 |

## 退役卡

每个候选填八项，填不完不删：

1. 测什么行为；
2. 非测试调用方是谁；
3. 检索命令（证明没人依赖）；
4. 更强的证明是什么（哪条测试/检查替代它）；
5. 历史（为什么加、对应哪个 bug）；
6. 删掉解锁了什么（时间、依赖、复杂度）；
7. 怎么验证删除没漏保护（跑全套 + 变异 sanity）；
8. 建议：删 / 合并 / 保留。

## 流程

1. 扫描，按模式分组；
2. 逐条填退役卡，不批量拍脑袋；
3. 按批给用户确认；一次最多删一类；
4. 删除后跑全套测试；有失败就回滚该批；
5. 把决定记进 `kelin-decision-log`，证据写 commit 或 PR。

## 保留底线

这些不删：

- bug 修复的回归测试；
- 钱、权限、数据写入的边界测试；
- 外部接口的契约测试；
- 用户明确要求保留的。

## 边界

- 默认只报告，不自动删；
- 一次只删一类，单独 PR；
- 不为了减少测试数量而删掉仍在保护行为的用例；
- 删完必须重跑测试，不凭眼力判断。
