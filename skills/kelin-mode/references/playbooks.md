# kelin-mode 轻量场景剧本（Playbooks）

除五条工程主轨道（`feature`/`fix`/`legacy`/`audit`/`light`）外，`kelin-mode` 内置四条贴近 `pstack` 的短平快场景剧本，避免把只读查代码、做探针、续做或盯 PR 错送进十阶段重型开发流程。

## 1. `investigate` — 只读调研与原理查证

适用：问“这段代码怎么跑的”“当初为啥这样设计”“帮我只读查一下报错原因/对比方案，别改代码”。

- **硬约束**：严格只读——**不改业务文件、不建分支、不跑 `setup --apply`、不进 `design/build/ship`**。
- **步骤**：
  1. 先查真实代码、提交历史与配置（需要背景时调 `kelin-recall` / `kelin-map`），禁止靠猜；
  2. 输出带 `文件:行号` 证据的解释（概览 / 核心链路 / 关键位置 / 坑点）；涉及方案取舍时附对比表与明确推荐，前提错了直接反驳；
  3. 走 `kelin-unslop` 去套话，结论落 `.kelin/investigation.md`（若已初始化状态机）。
- **收口**：若调研后决定改代码，**停下交给人拍板**，再重新路由进 `fix` 或 `feature`。

## 2. `prototype` — 快速原型与 10 行真探针

适用：外部接口/钩子通不通、两三种页面或交互方案拿不准，需要便宜地试出方向。

- **定位**：原型是**抛弃式实验工具**，目标是帮人做决策，不是可上线代码——不走重型 `plan-gate`/`review`/`ship`。
- **步骤**：
  1. 先写清这次原型要拍板哪一个问题（没决策问题就直接走 `feature`）；
  2. 在隔离草稿目录或临时脚本里做最小可运行样板（外部底座先跑 10 行真探针，界面对比尽量把候选方案做成可切换视图），不引入生产框架与多余抽象；
  3. 在真实运行面观察结果（日志、耗时或页面截图），把「观察结果 + 优缺点 + 推荐方向 + 草稿路径」写入 `.kelin/prototype.md`，明确标注**抛弃式**；
  4. 方向确认后，交回 `feature` 做正式实现与验证。

## 3. `resume` — 跨会话续做与安全暂停（`resume` / `pause`）

适用：“做到哪了、接着上次继续”“先暂停一下，留个干净交接点”。

- **续做（`playbook=resume`）**：
  1. 若 `.kelin/state.json` 未到 `done`，保留原 `mode`/`phase` 继续推进，不覆盖状态；
  2. 无活跃状态时，用 `kelin-recall` + `kelin-branches` 从分支、提交记录和未提交改动重建现场；
  3. 对照“已完成 vs 剩余待办”，不重复做已完成步骤，把续跑入口写入 `.kelin/handoff.md` 后切回对应主轨道。
- **安全暂停（`playbook=pause`）**：
  1. 不留半截挂起进程，确认工作区改动状态（未完成变更清楚标出位置，不强推、不乱删）；
  2. 用 `kelin-brief` 写清当前状态、已验证项、卡点与下次第一条命令，落盘 `.kelin/handoff.md`。

## 4. `babysit` — PR 值守与分支清理

适用：“盯着这个 PR，CI 挂了修掉”“看下评审评论”“清理已合分支和工作树”。

- **步骤**：
  1. 先核实当前盯的是哪个 PR / 分支，避免看错分支；
  2. 用 `kelin-watch` 拉日志判类（代码/环境/网络/权限），有代码根因再按小步修补并复验，无证据不瞎修；
  3. 逐条核对评审评论（区分真缺陷 / 可证据驳回 / 须人拍板），修完推送后再回复对应提交号；
  4. 合入前跑 `kelin-ship` 的 `merge-lane.mjs --pr <N>` 核对 HEAD 与 CI；分支清理用 `kelin-branches` 只报清单、确认后再删；
  5. 过程记录落 `.kelin/babysit.md`。**值守本身不等于部署授权，也不绕过合并门禁。**
