# 一句话简报

目标：让不看代码的人 30 秒内知道“现在等我什么、为什么、风险是什么”。

## 结构

先用一句话说清：**现在等你什么**。然后每项写四行：

- 事项：要做什么决定；
- 推荐：你建议选哪个，为什么；
- 证据：命令、文件、数字或链接；
- 风险：不这么做会怎样，或这么做的代价。

最后写下一步：谁在什么时候做什么。

## 规则

- 结论先行：先说要什么，再说过程；
- 每项必须给推荐，不把选项原样丢给用户；
- 证据给命令输出、文件位置或数字，不写“已测试”“应该可以”；
- 风险写清楚，不藏在最后一行；
- 没有待拍板事项就直说“现在没有需要你决定的”，不要硬凑；
- 不用 commit 数、测试数、代码行数代替结论；
- 术语第一次出现时用一句大白话解释；
- 一件事控制在 5 行以内，多件事每件 3-4 行。

## 模板

```markdown
## 现在等你
一句话：需要你决定 X，或者“现在没有需要你决定的”。

## 事项
### 1. 事项名
- 推荐：……
- 证据：`命令` / `文件:行` / 数字
- 风险：……

## 下一步
- 我做：……
- 你做：……
```

## 和其他 skill 的关系

- `kelin-mode`：每个阶段结束都可以用；
- `kelin-ship`：PR 说明先写“做了什么、怎么验证”；
- `kelin-unslop`：管文字去 AI 味，`kelin-brief` 管结构和决策；
- `kelin-recall`：重建上下文，`kelin-brief` 面向拍板。

## 反模式

- 铺垫三段才说重点；
- 列五个选项没有推荐；
- 用“应该可以”“理论上”代替证据；
- 把技术细节当结论；
- 没事找事，硬凑待办；
- 只报“做了什么”，不说“现在要你做什么”。
