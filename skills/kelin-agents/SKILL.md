# AGENTS.md 维护

AGENTS.md 不是项目说明书，是**给 agent 的硬约束清单**。写长了会变差，不是变好。

## 为什么必须短

2026 年 ETH 的研究（[arXiv 2602.11988](https://arxiv.org/abs/2602.11988)）测了三类 agent：LLM 生成的 AGENTS.md 让任务成功率降约 3%、成本涨 20% 以上；人写的短约束成功率升约 4%。模型不是忽略文件，是**太当回事**——每条都变成额外约束，探索和推理都变多。

主流建议（[agents.md](https://agents.md)、Anthropic 的 Claude Code 文档）：**100-150 行最有效，200 行是硬上限**。超过 150 行，收益开始反转。

## 只写四类东西

1. **反习惯的约束**：agent 默认会做错、但你能一句话纠正的。
   例：“用 `uv`，不用 `pip`”“测试和被测文件放同一目录”“不要引入新的日期库，用 `Intl`”。
2. **定义完成**：什么算做完。例：“`npm test` 和 `npm run lint` 都过才算完成”。
3. **成对的 don't/do**：只写 don't 会让 agent 反复试探。
   例：“不要用 `any`；未知类型用 `unknown` 并收窄”。
4. **决策表**：反复出现的歧义，用表固定选择。

## 不要写

- 目录结构、技术栈介绍、架构概览——agent 自己 `ls`、读 README 就能知道；
- 项目状态、谁在做什么、上周改了什么——这些会过期；
- 一次性任务的指令——放当次 prompt，不进文件；
- `/init` 自动生成的整篇概览；
- 秘密、真实数据、内部地址。

## 初始化（没有文件时）

用这个骨架，按项目填，**总数控制在 100 行内**：

```markdown
# AGENTS.md

## 怎么跑
- 安装：`<command>`
- 测试：`<command>`
- 构建：`<command>`

## 硬约束
- <agent 默认会做错、这里必须纠正的一条>
- <这一条要能验证：命令、文件或行为>

## 完成标准
- <命令 A> 和 <命令 B> 都通过

## 已知坑
- <踩过一次、下次还会踩的>

## 更深的文档
- 部署：[docs/deploy.md](docs/deploy.md)

## kelin-stack
- 跨文件、多步、产品类任务先 `/kelin-mode`；单文件小修直接做。
- 收尾先 `/kelin-neat` 对齐文档，再 `/kelin-reflect`。
```

没有命令可写就留空并注明“待补”，不要编。

## 审查（已有文件时）

```sh
node skills/kelin-agents/scripts/agents-check.mjs AGENTS.md
```

它检查：

- 行数：超过 200 直接失败，超过 150 警告；
- 重复：两条实质相同的规则；
- 断链：相对链接指向不存在的文件；
- 秘密：密钥特征；
- 个人路径：`/Users/<名字>/` 这类只在本机成立的路径；
- 占位：`TODO`、`TBD`；
- 空章节：标题下面没有内容；
- 命令区：有没有一节写清运行/测试/构建。

退出 1 表示有必须修的，0 表示只有警告或全过。

## 精简（太长了）

按顺序删，不要靠压缩措辞：

1. 删掉 agent 自己能发现的内容（目录结构、技术栈、架构）；
2. 删掉会过期的状态（进度、人员、日期）；
3. 合并重复规则，保留更具体的那条；
4. 把流程性内容移到 skill 或 `docs/`，在 AGENTS.md 留一行链接；
5. 把“必须永远/绝不”的规则改成可执行检查（lint、脚本、CI），文件里只留一句指路。

**先删后写。** 每条新规则都要能回答：这条 agent 自己发现不了吗？发现不了才留。

## 什么时候更新

- agent 重复犯了同一个错 → 加一条，并配一个反例；
- 命令变了 → 改命令，别在旁边补一句“以前是……”；
- 规则被证明没用 → 删掉，不要留着“以防万一”；
- 任务结束 → 用 `kelin-reflect` 判断值不值得写，不值得就不写。

更新只做**行级编辑**，写前重读，避免整篇重写把别人的规则冲掉。

## 多仓库与长文档

- 单仓：根目录一个 AGENTS.md；
- monorepo：根目录只放全局约束，子包各放一个短的，根里用链接指过去；
- 长内容：放 `docs/` 或 skill，AGENTS.md 只留索引。

## 和 kelin-mode 的衔接

- **intake**：先读 AGENTS.md。没有就 `init`；超过 150 行先 `trim`；`agents-check` 有失败项先修，再开工。
- **done / reflect**：只把这次真实踩过的坑写回，写完再跑一次 `agents-check`。
- 不要在每个阶段都往 AGENTS.md 里追加；它是长期约束，不是进度日志。

## 反模式

- 把 AGENTS.md 当 README 写；
- 每次任务后追加一段“本次改动”；
- 同一规则在三处重复；
- 写“写高质量代码”“注意安全”这种无法验证的话；
- 让 agent 自动生成整篇再原样提交。
