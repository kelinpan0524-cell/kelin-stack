# 正确性

“看着对”不是证据。**能让错误代码失败的检查**才是证据。

## 证据阶梯（从低到高）

| 级别 | 证据 | 能证明什么 |
| --- | --- | --- |
| 0 | 能编译 / 能跑 | 只能证明语法和导入没错 |
| 1 | 有测试且通过 | 证明测试覆盖的那几条路径 |
| 2 | 新测试在旧代码上失败 | 证明测试真的在测这个行为 |
| 3 | 边界矩阵全过 | 证明空、0、负数、重复、超长、并发 |
| 4 | 差分/性质对照 | 证明重写前后行为一致，或满足不变量 |
| 5 | 变异 sanity | 故意改坏一行，测试必须失败 |

日常至少做到 2 和 3；重写、迁移、钱和权限相关做到 4 和 5。

## 边界矩阵

每个新行为列一张小表，不要只测 happy path：

| 输入 | 期望 | 依据 |
| --- | --- | --- |
| 正常值 | … | 需求 |
| 空 / null | 明确报错或默认值 | 需求或既有约定 |
| 0 / 负数 | … | 业务规则 |
| 重复提交 | 幂等 | 业务规则 |
| 超长 / 超大 | 截断或拒绝 | 限制 |
| 并发 | 不丢、不重 | 事务或锁 |

表里每一行都要有一条断言。写不出期望的，先问需求。

## 重写和迁移：差分对照

同一个输入，同时喂给旧实现和新实现，比较输出。差异要么是 bug，要么是需求变更，不能“看起来差不多”。

```js
for (const input of cases) {
  assert.deepEqual(rewrite(input), legacy(input), JSON.stringify(input));
}
```

## 不变量：性质测试

适合纯逻辑、金额、排序、分页、去重：

- 排序后长度不变、元素集合不变；
- 分页所有页拼起来等于全集、无重复；
- 去重后长度 ≤ 原长度，且每个元素都还在；
- 金额计算：分转元再转分，误差为 0。

用随机输入跑 100-1000 次，比手写 10 个用例更容易撞到边界。

## 变异 sanity

改完代码，故意把关键一行改坏（比如把 `>=` 改成 `>`），跑测试：

- 测试必须失败 → 它在保护这个行为；
- 测试仍通过 → 这条测试是摆设，重写它。

改回来再跑一次，确认恢复绿色。一次就够，不要常态化。

## 测试本身要合格

- 一个测试一个行为；
- 断言结果，不断言内部调用顺序；
- 不 mock 掉真正要验证的东西；
- 失败信息能直接说出哪里错了。

## 输出

```markdown
| 行为 | 证据级别 | 怎么证明 |
| --- | --- | --- |
| 金额四舍五入 | 5 | 变异测试：把 round 改成 floor，断言失败 |
| 分页边界 | 4 | 性质测试：所有页拼接 = 全集 |
```

最后一列写不出可执行动作的，就是没证明。

## 反模式

- 先写实现再补测试，然后把当前输出存成期望值；
- 用覆盖率代替正确性；
- 只测一条正常路径就宣布完成；
- mock 掉数据库，然后声称“读写没问题”；
- 把“AI 说它测过了”当成证据。
