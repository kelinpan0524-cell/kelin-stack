# 正确性

“看着对”不是证据。**能让错误代码失败的检查**才是证据。

## 证据阶梯（从低到高）

| 级别 | 证据 | 能证明什么 |
| --- | --- | --- |
| 0 | 能编译 / 能跑 | 只能证明语法和导入没错 |
| 1 | 有测试且通过 | 证明测试覆盖的那几条路径 |
| 2 | 新测试在旧代码上失败 | 证明测试真的在测这个行为 |
| 3 | 边界矩阵全过 | 证明空、0、负数、重复、超长、并发 |
| 4 | 差分/性质对照 | 证明重写前后行为一致，或满足不变量 |
| 5 | 变异 sanity | 故意改坏一行，测试必须失败 |

日常至少做到 2 和 3；重写、迁移、钱和权限相关做到 4 和 5。

## 边界矩阵

每个新行为列一张小表，不要只测 happy path：

| 输入 | 期望 | 依据 |
| --- | --- | --- |
| 正常值 | … | 需求 |
| 空 / null | 明确报错或默认值 | 需求或既有约定 |
| 0 / 负数 | … | 业务规则 |
| 重复提交 | 幂等 | 业务规则 |
| 超长 / 超大 | 截断或拒绝 | 限制 |
| 并发 | 不丢、不重 | 事务或锁 |

表里每一行都要有一条断言。写不出期望的，先问需求。

## 重写和迁移：差分对照

同一个输入，同时喂给旧实现和新实现，比较输出。差异要么是 bug，要么是需求变更，不能“看起来差不多”。

```js
for (const input of cases) {
  assert.deepEqual(rewrite(input), legacy(input), JSON.stringify(input));
}
```

## 不变量：性质测试

适合纯逻辑、金额、排序、分页、去重：

- 排序后长度不变、元素集合不变；
- 分页所有页拼起来等于全集、无重复；
- 去重后长度 ≤ 原长度，且每个元素都还在；
- 金额计算：分转元再转分，误差为 0。

用随机输入跑 100-1000 次，比手写 10 个用例更容易撞到边界。

## 轻量形式化与幂等自查（可选）

不是所有项目都值得上 TLA+。先做轻量的：

- **高危状态索引**：并发/审批/库存/重试锁等高代价逻辑，记「代码符号 ↔ 不变量 ↔ `sync_commit`」；改动后重核，分清模型漂移与产品 bug；
- **崩溃与幂等两问**：写状态/文件/锁的流程连跑两遍结果一致吗？任意一步崩掉能凭现存状态自愈吗（临时路径写完再原子重命名）？
- 性质测试覆“永远成立”的约束；上 TLA+/TLC 先确认工具链与维护成本，反例须在真实代码复现；未做则写明。

## 变异 sanity

改完代码，故意把关键一行改坏（比如把 `>=` 改成 `>`），跑测试：

- 测试必须失败 → 它在保护这个行为；
- 测试仍通过 → 这条测试是摆设，重写它。

改回来再跑一次确认恢复绿色。再做**第二刀（行为而非实现）**：只改内部实现、保持外部行为不变，测试必须仍通过；若挂了说明绑死了实现细节。一次就够，不要常态化。

## 定位根因（原因不明时）

复现测试失败后仍然不知道为什么错？按手头线索选方法，见 [references/root-cause-methods.md](references/root-cause-methods.md)：

- 以前是好的 → 在临时 worktree 里 `git bisect` 二分到具体提交；
- 大日志 / CPU profile / Heap snapshot → **先用脚本抽成可查询表/热点行再定位**，禁止整份原始大文件塞进对话；
- 有一个错误的值 → 从输出往回追，在模块边界加临时日志，找"哪一步变错的"；
- 有正常对照 → 逐项换差异，最后换掉的那项是触发条件；
- 偶发 → 先固定不确定性（时区/种子/并发/共享状态），再修不确定性本身。

铁律：修在坏数据产生的地方，不在报错处挡症状；每行修复须有运行时证据，不顺手塞无证据预防补丁；**排查普遍问题按根因写法全仓搜索，不按报错信息搜索**。

## 测试本身要合格

- 一个测试一个行为；
- 断言结果，不断言内部调用顺序；
- 不 mock 掉真正要验证的东西；
- 失败信息能直接说出哪里错了。

## 输出

```markdown
| 行为 | 证据级别 | 怎么证明 |
| --- | --- | --- |
| 金额四舍五入 | 5 | 变异测试：把 round 改成 floor，断言失败 |
| 分页边界 | 4 | 性质测试：所有页拼接 = 全集 |
```

最后一列写不出可执行动作的，就是没证明。

## 反模式

- 先写实现再补测试，然后把当前输出存成期望值；
- 用覆盖率代替正确性；
- 只测一条正常路径就宣布完成；
- mock 掉数据库，然后声称“读写没问题”；
- 把“AI 说它测过了”当成证据。
