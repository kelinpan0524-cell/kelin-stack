# 目标契约

目标不是愿望。目标必须能被判定为“到了”或“没到”。

## 想跑 goal 但说不清

不要一上来让用户组织语言。**先给草稿，再让他改。**最多问三个问题，每个都带默认答案。

### 三个问题

1. **做完之后，你能做什么现在做不到的事？**
   - 用户答不出时，按请求猜一个最小可用结果，写成一句话给他确认。
2. **什么绝对不能碰？**
   - 默认：不改生产数据、不动权限、不发对外消息、不删现有分支。
3. **怎么算做完？**
   - 用户答不出时，替他提一条可执行检查（命令、页面或数字），让他确认。

每个问题都可以回答“你定”，那就用默认值继续，不要卡住。

### 产出

1. `goal.md`：用下面的模板；
2. `plan.md`：轻量三行（目标 / 验收 / 下一步）；跨文件再升级成标准计划；
3. 一行可直接粘进 ZCode 的命令。

### 给 /goal 的命令

写成一整行，用户复制即可：

```
/goal 让报价单支持批量导出；完成条件：export-test 退出 0、1000 行导出 < 10s；约束：不改报价计算、不出现客户手机号
```

然后问一句：“确认这个目标就开始跑，还是先改哪一条？”

### 跑起来

用户确认后，按 `kelin-mode` 的 `light` 或 `feature` 推进；每个检查点停下来给人看，不要一路跑到底。

## 四件事

1. **一句话目标**：谁，在什么场景，能做什么之前做不到的事。
2. **完成条件**：每条都能执行——命令、接口、页面、数字。
3. **约束**：不能碰什么（数据、目录、接口、时间），以及最坏能接受什么后果。
4. **检查点**：中途在哪几个点停下来给人看，而不是做完才汇报。

## 写下来

`goal.md`：

```markdown
# 目标
让报价单支持批量导出，业务员不用再逐条复制。

# 完成条件
- [ ] `node scripts/export-test.mjs` 退出 0
- [ ] 导出的 xlsx 行数 = 询价行数，且含 quote_id 列
- [ ] 1000 行导出耗时 < 10s

# 约束
- 不改现有报价计算逻辑
- 不引入新的付费依赖
- 导出文件里不能出现客户手机号

# 检查点
- 数据模型定稿后停一次
- 接口跑通后停一次

# 拍板人
Arono
```

## 校验

```sh
node skills/kelin-goal/scripts/goal-check.mjs goal.md
```

它检查：目标非空、至少一条完成条件、约束非空、检查点非空。缺哪项报哪项。

## 和 ZCode `/goal` 的关系

ZCode 的 `/goal` 管“这次会话往哪走”；`goal.md` 管“到了算什么”。先把 `goal.md` 写清楚，再用 `/goal` 把目标设进会话，两者指向同一件事。

## 反模式

- 完成条件写“体验更好”“性能优化”；
- 约束为空，等于允许无限扩大范围；
- 没有检查点，做完才发现方向错；
- 目标里塞了三件不相关的事。
